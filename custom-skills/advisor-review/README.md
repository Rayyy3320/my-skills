# advisor-review（顾问模式）

## 这是什么

一个可选的双模型协作模式：在主执行者旁边加一个**只读**的第二模型作为评审/顾问。
**加载本 skill = 模式开启**（当前会话/当前波次生效）；卸载或新会话未加载即恢复单执行者流程。仅在用户明确要求开启（如"开启顾问模式 / advisor mode"）时才加载。

## 模式铁律

1. **决策权唯一**：主执行者（+ 用户）拥有全部写入权与最终裁量；顾问只读、只建议，产出是"发现清单"，不是任务清单。
2. **顾问永不写**：不改文件、不跑测试、不执行命令。
3. **按需启停**：随用随开，关闭不留任何状态，也不在仓库文档中留痕迹。
4. **与治理体系正交**：可配合 project-governance 使用，也可独立用于任何项目。

## 三个使用时机

| 时机 | 触发条件 |
|---|---|
| 波次边界评审 | 共享层（契约/数据形状）有改动的波结束时 |
| 疑难升级 | 同一 bug 主执行者两轮未修复 |
| 设计预审 | 大型机制开工前（一次性） |

## 怎么用

- **评审请求走封闭合同**：只读角色 + 精确范围（文件/diff 清单 + ≤3 个问题）+ 输出格式（按 blocker / major / minor / nit 分级，每条含位置、依据、建议）+ 治理文档路径。
- **疑难 bug 发"升级咨询包"**：最小复现 + 期望 vs 实际 + 已尝试路径与排除项 + 一个具体问题。禁止粘贴整段历史。
- **发现由主执行者 triage**：采纳（排期）/ 拒绝（一行理由）/ 存疑（交用户仲裁），结果回传用户——拒绝不解释超过一行，防止评审驱动发散。

## 可迁移性

对顾问模型不做任何假定（Codex / GPT / Claude 等均可）。若顾问生态原生读取项目常读文档（如 AGENTS.md），治理规则自动对其生效，无需重复传授。
