# project-bootstrap（项目底座）

## 这是什么

为一个新项目、或一个**确实**缺少可靠执行路径与可发现技术 Authority 的仓库，建立**最小**的可运行、可修改、可验证的技术底座。

只建当前目标与证据所支持的最小基础，不预置任何既定架构。

## 何时用

- 新项目初始化；
- 存量仓库找不到可靠运行入口、技术 Authority 不可发现时的底座恢复。

## 不做什么

- 不做成熟项目的架构重构（见 **project-governance** 的治理范畴）；
- 不做治理评审、日常开发或无关清理；
- 不写投机性的分层、服务、部署单元、注册表、依赖图、文档体系、治理设施、健康扫描或"面向未来"的抽象；
- 不持久化计划、调研笔记、设计探索、临时图示或 bootstrap 推理过程。

## 流程要点

1. 从目标与约束出发；存量仓库先摸清当前谁在真正控制执行，再提结构。
2. 只建立四件事：一条可靠的运行路径；必须恒真的东西及其最省的验证方式；哪些已证实的高代价副作用需要隔离；哪些当前决策贵到值得现在就定结构。
3. 尽量复用已有结构，只加/改缺失底座真正需要的部分。
4. 每个必须保持一致的耐久事实只留一个 Authority，且能从它所约束的代码本地发现。优先级同治理：代码 → 机械校验 → 可靠推导 → 最后才是持久化文档。
5. 只有当减少的传播/回退成本超过生命周期成本时才加边界；局部性退化时先删重复与多余传播，再谈抽象。
6. `AGENTS.md` 只写无法从仓库廉价推断的、耐久的项目专属约束，不趁机立通用治理。
7. 用最小的相关检查验证运行路径与受影响的不变量，跑通即停。

## 收尾

交付前清掉 bootstrap 自身引入的重复规则、多余文件和投机机制。

## 配套

- **project-governance**：项目已有底座后的治理审计与最小修复，与本 skill 正交。
