# selector-UI-patch

组件市场是**索引**，不是源头。思路只有一条：**先判断源码在哪，再决定怎么拿。**

## 四条判断

1. **优先找上游。** 市场收录的组件多来自开源库，上游免费开放且代码更全。
   实测同一个组件：`magicui.design/r/<name>.json` → 200（189 行），
   `21st.dev/r/...` → 403。能在上游拿，就别在市场里抠。
2. **区分「拿不到」和「没找对地方」。** 市场页抠不出来时，先想「源码在不在别处」，
   而不是「我的解析够不够好」。
3. **信息不在场 ≠ 技巧不够。** 页面 HTML（含 RSC payload）里没有，就是没有。
   实测某组件页 308KB，`const/function X` 出现 **0 次** —— 改 UA、剥标签、换 cookie
   全部无效。判定后立刻换通道，不要重试。
4. **降级要有终点。** 原始源码确实不可得时，预览 iframe 的**渲染 DOM + Tailwind class**
   足以重建等效实现。这是「任意组件都有出路」的兜底。

## 通道优先级

| 优先级 | 通道 | 能拿到 | 适用 |
|---|---|---|---|
| 1 | 上游开源站 / GitHub | **完整源码** | 组件有公开出处 |
| 2 | 市场页 SSR 下发 | **完整源码** | free 组件 |
| 3 | 预览 iframe 的 DOM + class | **等效实现**（保 UI，不保复杂逻辑） | 兜底，任何组件 |

（`scripts/` 下有执行器，直接调用：`registry.py` 走通道 1，`extract.py` 走通道 2。）

## 防呆

- **别把用法示例当源码** —— 5~30 行、`import X from "@/components/ui/x"`、直接 `return <X/>`
  是薄壳，不是组件实现
- **别在死路上重试** —— 通道 2 判定「源码未下发」后，重试多少次结果都一样
- **列表页不含源码** —— 必须进详情页

## 边界（要如实告知用户）

「任意组件都有处置路径」≠「任意组件都能拿到原始源码」。
作者自制且无公开出处的组件，通道 1、2 都拿不到，只能走通道 3 得到等效实现，
或如实说明拿不到、建议换组件。不要为了让结果好看而假装拿到了源码。
